# 农场视觉品质升级设计

> 日期：2026-07-29
> 窗口：ARCH-11
> 状态：已获用户批准，进入分阶段实施
> 前置设计：`docs/superpowers/specs/2026-07-26-farm-system-design.md`

## 1. 背景与目标

现有农场首发玩法、事务、计时、生命周期和响应式布局已经完成并通过验证，但表现层主要由深色 Dashboard 卡片、Emoji 和常驻文字构成。功能信息完整，整体观感仍像管理面板中的农场模块，缺少完整场景、统一美术语言和经营反馈。

本次升级的目标是：

- 将农场从“Emoji 与文字组成的功能页”升级为具有完整空间、光影和生命感的高质量 2D 卡通场景。
- 保留现有农场的全部产品语义、状态结构、事务权威和测试基础。
- 让农田、加工与订单形成统一的农场世界，而不是三个视觉割裂的后台页面。
- 建立可扩展的美术资产协议，支持后续增加作物、土地效果、建筑、配方、订单、多形态和外部皮肤包。
- 为未来可能采用 Godot 保留清晰迁移边界，但不在首轮引入第二套引擎和构建链。

本次不是 QQ 农场或 Hay Day 的临摹项目。参考产品仅用于拆解固定场景、对象化入口、信息层级和统一美术体系；所有正式素材必须原创。

## 2. 已锁定的产品方向

### 2.1 美术方向

- 圆润、明亮、温暖的高质量 2D 卡通。
- 对象具有体积、统一光源、柔和阴影和清晰轮廓。
- 固定斜俯视构图，兼顾 QQ 农场式清晰布局与成熟经营游戏的场景质感。
- 不采用像素风，不采用写实风，不采用 3D。
- 不以“把 Emoji 换成图片”作为完成标准；背景、土地、作物、建筑、特效和 HUD 必须属于同一视觉系统。

### 2.2 场景边界

- 首轮镜头固定，不支持拖动或缩放。
- 同屏完整展示当前 `4×4` 农田、农舍、水渠、围栏、草地和少量环境装饰。
- 不新增自由大地图、道路铺设、装饰摆放或镜头导航。
- 现有逐格扩田、土地升级和建筑占格语义保持不变。

### 2.3 交互入口

- 加工台与订单板作为场景中的可点击建筑。
- 顶部继续保留“农田 / 加工 / 订单”三个快捷入口。
- 场景入口与顶部入口进入同一业务页面，不维护两套状态。
- 场景渲染失败时，顶部入口仍可使用。

### 2.4 宠物角色

- 奶油星团出现在农场场景边缘，作为纯视觉陪伴角色。
- 可播放克制的待机、看向农田、打哈欠或关注小鸟等表现。
- 点击可显示轻量气泡或引导视觉焦点。
- 不自动播种、收获、加工，不改变效率、饱腹或心情。
- 不改变桌宠窗口既有 idle、sleep、喂食和一次性动作语义。

### 2.5 动效强度

- 使用中等、持续但不喧闹的动效。
- 环境可包含缓慢水面、云影和植物摆动。
- 作物成熟使用柔和高光或呼吸感。
- 洒水器、加工台、小鸟和宠物使用局部循环动画。
- 播种、收获、扩地、土地升级、加工完成和订单交付使用短促反馈。
- 不使用持续满屏粒子或所有对象同步大幅运动。
- `prefers-reduced-motion: reduce` 下停用非必要循环动画并压缩一次性反馈。

## 3. 首轮范围

### 3.1 包含

- 农场固定主场景。
- `4×4` 农田、土地等级、锁定/可扩建状态。
- 六种作物的多阶段视觉。
- 三种建筑的等级与工作状态视觉。
- 加工台和订单板场景入口。
- 农田、加工、订单的统一 HUD、页签、按钮和反馈样式。
- 加工页的工坊式视觉重构。
- 订单页的木质订单板式视觉重构。
- 奶油星团农场陪伴形象。
- 小鸟视觉升级。
- 农场物品在仓库、商店和桌宠提醒中的统一图标。
- Canvas 加载、运行和销毁失败时的功能回退。
- 600×400 与 800×600 两档 Dashboard 基准验证。

### 3.2 不包含

- 自由大地图、镜头拖动或缩放。
- 自由摆放道路、建筑或装饰。
- 第二农田、特殊农田、温室、养殖和天气系统。
- 宠物自动劳作、寻路、生产效率或饱腹消耗。
- 新作物、新建筑、新配方、新订单规则或经济调整。
- 全 Dashboard 视觉重做。
- 背景音乐、音效和声音设置。
- Godot/Unity 工程、Web 导出或宿主桥接。
- 直接使用或临摹第三方游戏素材。

## 4. 技术架构

采用“现有业务权威＋PixiJS 场景适配器＋DOM 经营界面”。

```text
FarmService / PetState / EventBus
              │
              ▼
现有 Farm view model 与页面协调器
              │
       纯视觉场景快照
              ▼
      Pixi FarmSceneAdapter
              │
       用户意图 / 视觉事件
              ▼
DOM HUD / 操作面板 / 加工 / 订单 / Overlay
```

### 4.1 保持不变

- `farm-config.mjs` 中的数值与解锁配置。
- `farm-state.mjs` schema v1 和迁移。
- 种植、成熟、产量、建筑、加工和订单纯规则。
- `farm-service.js` 的串行事务、一次提交和事件顺序。
- PetState、统一库存、EventBus 和弱提醒。
- Dashboard 的动态模块挂载与页面 cleanup 契约。

### 4.2 PixiJS 的职责

- 加载并管理场景纹理、spritesheet 和动画资源。
- 渲染背景、农田、作物、建筑、宠物、环境层和特效层。
- 将逻辑坐标适配到实际 Canvas 尺寸。
- 提供对象命中区域、hover、focus 镜像和选中视觉。
- 接收外部一次性视觉指令并播放反馈。
- 在暂停、页面隐藏或减少动态效果时降低或停止非必要动画。
- 在销毁时释放 ticker、监听器、纹理引用和迟到回调。

### 4.3 PixiJS 禁止承担

- 读取或修改 PetState。
- 调用库存增减或 FarmService 业务命令。
- 计算成熟、产量、建筑效果、价格或奖励。
- 自行持久化选择、动画或节点状态。
- 从视觉动画结束推导交易是否成功。
- 在业务提交前显示不可逆的成功结果。

## 5. 最小场景接口

首轮只建立当前需求需要的窄接口，不预先实现通用游戏引擎框架。

### 5.1 输入快照

场景快照只包含表现需要的稳定数据：

```js
{
  farmLevel,
  coins,
  activeTab,
  selectedObject,
  motionReduced,
  summary: {
    matureCount,
    processingCount,
    readyOrderCount
  },
  tiles: [{
    tileId,
    row,
    col,
    occupancy,
    landLevel,
    unlockState,
    cropId,
    cropStage,
    mature,
    buildingId,
    buildingType,
    buildingLevel,
    buildingWorking
  }],
  pet: {
    visible,
    moodTier
  },
  bird: {
    birdId,
    visible,
    claimBusy
  }
}
```

`cropStage` 是时间状态到视觉阶段的派生值，不持久化。首轮默认分为四阶段：

1. 刚播种
2. 幼苗
3. 生长
4. 成熟

阶段阈值由视觉配置按总生长进度派生，不改变真实成熟时间和产量。

### 5.2 输出意图

场景只向页面层发送用户意图：

```js
{ type: 'select-tile', tileId }
{ type: 'open-processing' }
{ type: 'open-orders' }
{ type: 'claim-bird', birdId }
{ type: 'click-pet' }
```

页面层验证当前 generation、busy 状态和业务前置条件后，才决定是否调用命令。

### 5.3 生命周期

```js
mount(container, options)
update(snapshot)
resize(width, height, devicePixelRatio)
setPaused(paused)
setReducedMotion(reduced)
playEffect(effect)
destroy()
```

所有公开调用在 `destroy()` 后安全无操作。初始化 Promise、资源加载和视觉效果必须带 generation 守卫。

## 6. 场景空间与图层

采用统一设计基准画布，运行时等比缩放并居中裁切安全留白，不改变对象相对位置。

从后到前：

1. **天空与远景层**：天空、远山、云影。
2. **地表层**：草地、水渠、道路痕迹和整体地面阴影。
3. **后景装饰层**：农舍、树木、围栏、风车或储物设施。
4. **农田底层**：16 格土地、锁定区域和土地等级材质。
5. **农田内容层**：作物、洒水器、稻草人、堆肥箱。
6. **经营建筑层**：加工台、订单板及可点击提示。
7. **角色与彩蛋层**：奶油星团、小鸟。
8. **交互层**：hover、选中、移动目标和可扩建提示。
9. **特效层**：播种尘土、收获飞出、金币、解锁光效。
10. **DOM HUD 层**：摘要、页签、反馈和操作面板。

遮挡顺序由固定层级和对象底部锚点共同决定。首轮没有自由摆放，不引入通用寻路或地图排序系统。

## 7. 农田视觉状态

### 7.1 土地

- `locked`：草地或未开垦区域，不使用单独的锁 Emoji；以木牌、覆盖草皮和弱化饱和度表达。
- `unlock-eligible`：木桩、虚线边界或柔和高亮表达可扩建。
- `land Lv.1`：普通棕土，垄沟较浅。
- `land Lv.2`：更深、更湿润的肥沃土，边缘有少量嫩草。
- `land Lv.3`：饱满暖棕土和轻微金色肥力粒子，减少动态效果时静止。
- `selected`：对象下方柔和描边或地面光圈，不改变地块尺寸。
- `move-target`：绿色边缘提示；减少动态效果时不用脉冲。

土地等级必须通过材质和色彩直接可辨，右下角等级文字只作为辅助信息。

### 7.2 作物

每种作物至少四阶段，并满足：

- 同一地块、相同透视和相同根部锚点。
- 阶段只改变视觉，不改变业务状态。
- 成熟作物与未成熟作物无需读取文字即可区分。
- 成熟后永久保持成熟视觉，不表现枯萎。
- hover 或选中后再显示名称、剩余时间和预计产量。

### 7.3 建筑

- 洒水器：等级影响主体尺寸或装饰复杂度；工作时低速局部摆动或水滴反馈。
- 稻草人：等级影响服饰、帽子或支撑结构；工作状态使用轻微布料摆动。
- 堆肥箱：等级影响箱体和植被丰富度；工作时偶尔出现小叶片。
- 建筑工作锁定通过场景状态与操作面板共同表达，不新增业务状态。

## 8. 加工与订单页面

### 8.1 加工页

- 场景中的加工台点击后进入加工页。
- 加工页使用“工坊设备＋配方架＋三槽生产轨道”的视觉结构。
- 当前运行任务位于设备主体附近，显示清晰进度。
- 后续排队任务表现为待加工托盘或队列卡。
- 配方使用统一插画图标和材料数量，不使用 Emoji。
- 材料不足、未解锁、队列已满继续使用现有禁用语义。
- 取消 queued 任务仍使用现有确认 overlay 和全额返还规则。

### 8.2 订单页

- 场景中的订单板点击后进入订单页。
- 页面主体表现为木质订单板和三张独立订单纸。
- 需求、持有量和奖励使用统一物品图标。
- 可交付订单使用印章、高亮或轻微纸张浮起表达。
- 冷却槽显示空钉位、替换提示和倒计时。
- 整单交付和放弃冷却规则保持不变。

### 8.3 DOM 与 Canvas 边界

加工和订单主体首轮继续使用 DOM，以保证：

- 中文文字清晰。
- 倒计时和禁用状态容易测试。
- 键盘与屏幕阅读器可访问。
- 不把复杂列表和滚动行为搬入 Canvas。

DOM 视觉需要使用正式背景纹理、图标和统一颜色，不等于保留当前通用深色卡片。

## 9. HUD 与信息层级

顶部摘要继续提供：

- 农场等级与经验。
- 成熟田地数。
- 加工队列状态。
- 可交付订单数。
- 金币。

优化原则：

- HUD 使用少量半透明卡片或统一木质/奶油色控件，不遮挡核心农田。
- 默认不在每格常驻显示作物名称、倒计时和“田 Lv.X”。
- 田块详细数据在 hover、键盘 focus 或选中后的 DOM 操作面板显示。
- 成熟、锁定、可扩建、工作中等关键状态必须同时具有颜色之外的形状或图标线索。
- `600×400` 下优先保证农田可点击、页签可达和主要摘要可读；次级文案可折叠。

## 10. 美术资产协议

### 10.1 素材来源

- 允许 AI 辅助生成原创素材。
- 禁止直接使用、描摹或风格复刻第三方游戏的受保护素材。
- AI 输出必须经过人工筛选、拆层、修边、透明通道检查和一致性复验。
- 若垂直样张无法稳定满足统一透视、光源和跨阶段一致性，ARCH-11 必须向用户报告并建议外部 2D 美术支持。

### 10.2 统一规范

设计锁定以下规则后才批量生产：

- 固定斜俯视角。
- 主光源方向、色温和阴影软硬度。
- 统一轮廓强度与边缘处理。
- 统一饱和度与明度范围。
- 地块逻辑尺寸和对象安全边界。
- 每类对象的脚底锚点。
- 文件命名、像素密度、透明留白和导出格式。

### 10.3 资产组织

建议结构：

```text
assets/farm/<skin-id>/
├── farm.json
├── background/
├── land/
├── crops/<crop-id>/
├── buildings/<building-id>/
├── pet/
├── bird/
├── effects/
└── ui/
```

`farm.json` 记录：

- schema version
- 设计基准尺寸
- 逻辑坐标与锚点
- 资源路径
- 动画帧与帧时长
- 回退资源
- 可选皮肤能力

清单不得保存业务价格、产量、解锁等级或奖励。

### 10.4 首轮资产清单

- 一套完整分层背景。
- 三种土地等级、锁定和可扩建状态。
- 六种作物 × 至少四阶段。
- 三种建筑 × 三级主体及工作动效。
- 加工台、订单板和农舍。
- 奶油星团农场待机素材。
- 小鸟和奖励反馈。
- 播种、收获、成熟、解锁、土地升级、加工完成、订单交付特效。
- 作物、种子、建筑、加工品和订单奖励图标。
- HUD、页签、按钮、订单纸和工坊组件纹理。

## 11. 垂直样张门槛

批量制作前只制作一个最小闭环样张：

- 一张固定农场场景构图。
- 一块 Lv.1 土地。
- 一种作物的四阶段。
- 一座建筑的三个等级和一个工作状态。
- 奶油星团农场待机。
- 一次播种与一次收获反馈。
- 一张加工配方卡和一张订单纸。

样张必须在 `800×600` 和 `600×400` 实际内容区域验证：

- 透视一致。
- 光源一致。
- 对象没有明显 AI 形变或拼贴感。
- 作物阶段一眼可辨。
- 田块命中区域足够。
- 文本与图标不遮挡主场景。
- 资源尺寸和显存预算可接受。

样张不通过时不得批量生产。应先修订美术规范；连续无法通过时，上报外部美术需求。

## 12. 动画与反馈

### 12.1 环境循环

- 水面、云影、少量植物和角色待机使用低频循环。
- 页面隐藏、切出农场或 Dashboard 销毁时暂停。
- 重新显示时从安全状态恢复，不补播离线动画。

### 12.2 事务反馈

业务提交成功后才播放：

- 播种落土。
- 收获作物飞向库存摘要。
- 金币飞向 HUD。
- 土地解锁或升级。
- 建筑建造、移动、升级、拆除。
- 加工入队、完成。
- 订单交付。

失败命令只显示失败反馈，不先播放成功动画。重复点击继续由现有 busy gate 和 FarmService 串行队列防重。

### 12.3 离线结算

离线回来时只展示最终正确状态和一条克制摘要，不为每个离线完成事件逐个补播动画。

## 13. 响应式与可访问性

- PixiJS 使用固定逻辑画布，按容器等比缩放。
- `devicePixelRatio` 需要设置上限，避免高 DPI 显存无界增长。
- 关键对象命中区不能小于视觉对象本身，且不得互相覆盖造成误触。
- Canvas 外维护与场景对象对应的可访问 DOM 控件或列表。
- 键盘 focus 必须同步场景高亮；场景点击必须同步 DOM 选中态。
- 加工、订单、确认和倒计时继续由原生 DOM 表达。
- 颜色不是唯一状态线索。
- `prefers-reduced-motion`、页面可见性和模块 cleanup 共同控制动画。

## 14. 性能预算与加载

首轮设计目标：

- 首屏先显示静态场景占位，再异步加载完整动画资源，避免空白或 Emoji 闪变。
- 资源按场景基础、当前可见作物/建筑、加工/订单 UI 分包。
- 不预加载未来未解锁内容的全部高分辨率动画。
- 合并小图到 spritesheet，减少纹理切换与文件请求。
- 限制同时运行的循环动画和粒子数量。
- 页面隐藏或切出农场后暂停 ticker。
- cleanup 后没有 RAF、ticker、timer、DOM 监听或迟到 Promise 修改旧页面。
- 性能阈值需在实施计划中通过技术原型测量后锁定，不在本设计中虚构具体帧率或显存数字。

## 15. 加载失败与回退链

从优到劣：

```text
完整 PixiJS 动态场景
→ 静态分层场景＋DOM 操作
→ 简化 DOM 4×4 农场
```

要求：

- manifest 失败、关键纹理失败或 Pixi 初始化失败时自动降级。
- 单个非关键装饰失败只隐藏该装饰，不使整个场景失败。
- 关键对象缺图时使用项目自有中性占位图，不使用第三方或系统 Emoji 作为正式成功态。
- 简化 DOM 回退必须支持农田、加工、订单全部既有操作。
- 降级不得改变计时、事务、库存或提醒状态。
- 同页可安全重试资源加载；失败 cleanup 后重新进入农场也可重新初始化。

## 16. 测试与验收

### 16.1 自动测试

- 场景快照派生不改变输入。
- 四阶段作物视觉边界及成熟状态。
- PixiJS 意图不会直接触发状态写入。
- 业务成功后才发视觉效果。
- 重复点击、busy gate 和迟到回调。
- 页面隐藏、切页、cleanup 和重新挂载。
- resize、DPR 上限和 600×400 / 800×600 布局。
- 减少动态效果。
- manifest 校验、关键/非关键资源失败和三级回退链。
- 单个贴图失败不会泄漏 ticker 或监听器。
- 加工、订单、仓库入口和键盘后备。
- 全仓既有测试不得回归。

### 16.2 人工视觉验收

- 两档 Dashboard 尺寸与窗口连续缩放。
- 普通、肥沃、丰饶土地直接可辨。
- 六种作物四阶段与成熟状态可辨。
- 三种建筑三级及工作状态可辨。
- 场景入口和顶部入口一致。
- 农田、加工、订单的视觉语言统一。
- 奶油星团不遮挡田地和操作。

- 完整加载、静态回退、DOM 回退分别可操作。
- 长时间停留、频繁切页和重复进入不出现卡顿或残留动画。
- 正常动态与减少动态效果都完成肉眼验收。

## 17. 实施分阶段建议

本设计获批后，实施计划应至少分为：

1. **美术规范与垂直样张**
   不改生产业务代码；验证构图、统一性、阶段和小窗口可读性。
2. **PixiJS 技术原型与场景边界**
   新依赖、最小适配器、快照/意图、生命周期、失败回退和性能测量。
3. **农田完整场景与资产批量生产**
   16 格、土地、六作物、三建筑、宠物、小鸟和事务反馈。
4. **加工与订单统一换肤**
   工坊、订单板、物品图标和场景双入口。
5. **跨页图标、回退链与最终集成**
   仓库/商店/提醒图标、全矩阵回归、性能和视觉验收。

具体窗口数量、编号、执行方和允许文件必须在实施计划完成后另行推荐，并取得用户明确确认。不同窗口不得同时修改同一文件。

## 18. Godot 长期待定方向

Godot 不属于本次实施范围。未来出现以下两项及以上正式需求时，重新做引擎评估：

- 可拖动或缩放的大地图。
- 道路、建筑和装饰自由摆放。
- 宠物在农场中寻路和劳作。
- 大量 NPC、动物、碰撞和遮挡。
- 昼夜、天气、季节和复杂粒子。
- 农场脱离 Dashboard 成为主要游戏世界。
- 独立移动端或游戏版本发行。

届时优先评估保留 JavaScript 业务权威、以 Godot 替换场景适配器；是否进一步迁移业务规则必须单独决策。当前只通过稳定 ID、通用素材格式、纯快照、用户意图和生命周期保持可迁移性，不提前建设 Godot Bridge。

## 19. 重要决策上报点

实施期间遇到以下情况必须停止扩围并向用户/架构窗口报告：

- 垂直样张无法达到统一高质量 2D 卡通标准。
- 需要外部专业 2D 美术、付费素材或带额外许可的动画工具。
- PixiJS 原型无法满足小窗口性能或回退要求。
- 需要新增持久化字段、IPC、FarmService 命令或业务事件。
- 需要改变农场 schema、经济、计时、提醒或宠物动作语义。
- 需要引入 Godot、Unity、Spine、Rive 或其他新运行时。
- 安装包体积或资源体积明显超出当前可接受范围。
- 现有 Dashboard 架构无法安全承载场景生命周期。
